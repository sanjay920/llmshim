# 0007: TLS termination and certificate renewal

Status: server TLS and renewal implemented. Mutual TLS is in 0011.

## What it is

```toml
[server.tls]
cert_file = "/etc/llmshim/tls/tls.crt"   # PEM chain, leaf first
key_file  = "/etc/llmshim/tls/tls.key"   # PEM private key
reload_interval_secs = 30                # default 30, 1 to 86400

[admin.tls]        # optional, the same fields, for the admin listener
```

With `[server.tls]` the main listener speaks TLS; without it, plain HTTP, as
before. The admin listener has its own table, so a probe or scraper inside the
pod can stay on plain HTTP while callers get TLS (or the reverse). The startup
banner shows `https://` for a listener that terminates TLS.

TLS reuses the plain server's limits: the same connection cap and the same
first-headers deadline, which now also bounds the handshake, so a client that
connects and sends nothing cannot hold a connection open. HTTP/1.1 and HTTP/2
are both served (ALPN).

## Renewal without a restart

Certificate managers renew by replacing the files. The server compares a digest
of both files every `reload_interval_secs` and, when either changed, loads the
pair and swaps it in. New connections get the new certificate; connections that
are already open finish on the one they began with.

- **A replacement that does not load is ignored.** A half-written pair, or a
  certificate whose key has not been replaced yet, is reported once on stderr
  and the previous certificate stays in service. The next change is tried
  again, so a renewal that lands in two steps completes on the second.
- Changes are detected by content digest, not timestamp or size: a renewed
  certificate is often the same length, and some filesystems keep one-second
  timestamps.
- A symlink swap (the usual Kubernetes secret update) is followed.

## What `--check` and startup verify

The pair is loaded before anything is created or started, so a missing file, an
unparsable PEM, or a key that does not belong to the certificate exits 1 with the
file names. Messages never contain file contents.

## Decisions

- **Files, not references.** Unlike provider keys, the certificate and key are
  read from paths and not through `{ env }`: a PEM chain is not a good
  environment value, secret volumes are the normal delivery, and renewal needs a
  file to watch.
- **One certificate per listener.** No SNI selection among several. Put several
  names in the certificate.
- **The crypto provider is ring**, as for the managed proxy. No FIPS validation;
  a FIPS build is a separate roadmap item.

## Not done
